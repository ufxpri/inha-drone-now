# 🛩 드론 지금 당장 (inha-drone-now)

> **Java Swing 기반 통합 드론 비행 안전 정보 조회 데스크톱 애플리케이션**
> 사용자가 비행하려는 위치를 지도에서 클릭하면, 분산된 기상·항공 규제 정보를 한곳에 모아

## 📌 기획 배경

안전하고 합법적인 드론 비행을 위해서는 다음을 모두 확인해야 합니다.

- 기상 상태 (풍속·강수 등)
- 일출·일몰 시간 (야간 비행 제한)
- 비행금지·제한구역, 관제권
- 실시간 항공고시보(NOTAM)

그러나 이 정보들은 **기상청, 국토교통부, 한국천문연구원 등 부처별로 분산**되어 제공되어,
비행 전 사용자가 직접 수집·대조해야 하는 불편과 안전상의 위험이 있습니다.

본 프로젝트는 비행 위치를 기준으로 산재된 제약 요소를 **한 화면에 종합 수집·시각화**하여,
비행 가능 여부를 직관적으로 제시하는 통합 데스크톱 애플리케이션입니다.

*(기획 상세는 `기말자료/10주차_보고서`, 클래스 설계는 `기말자료/12주차_클래스설계보고서` 참조)*

## ✨ 주요 기능

| 기능 | 설명 |
|---|---|
| 🗺 **지도 기반 위치 선택** | 지도를 클릭해 비행 예정 위치(위경도) 지정 |
| 🌤 **실시간 기상 조회** | 풍속·풍향·강수·기온 (게이지·나침반·온도계로 시각화) |
| ☀ **일출/일몰 표시** | 주간 비행 가능 시간대를 타임라인으로 표시 |
| 🚫 **공역 폴리곤 표시** | 비행금지·제한·관제권 등 9종 공역을 지도에 색상별 폴리곤으로 렌더링 |

| 📍 **관심 지점 저장** | 현재 클릭 위치를 즐겨찾기로 저장(파일 영속화) |

## 🧩 데이터 소스

| 구분 | 출처 | 연동 방식 |
|---|---|---|
| 기상 (초단기실황) | 기상청 / 공공데이터포털 | REST API (JSON) + 위경도→격자 변환 |
| 일출·일몰 | 한국천문연구원 / 공공데이터포털 | REST API (XML) |
| 항공고시보(NOTAM) | 국토교통부 항공정보포털 | 세션 기반 POST → JSON 파싱 |
| 비행금지·제한구역 등 | 국토교통부 / V-World | GeoJSON 9종 번들 (EPSG:3857→WGS84 변환) |

> NOTAM은 일반 공개 OpenAPI가 없어 항공정보포털의 조회 엔드포인트를 분석해 연동했고,
> 공역 데이터는 V-World WFS에서 수집한 GeoJSON을 번들하여 오프라인에서도 안정적으로 동작합니다.

## 🏗 아키텍처

12주차 클래스 설계 보고서를 기반으로 한 MVC 구조입니다.

```
com.drone
├── model            도메인·값 객체 (Location, Spot, PilotLicense, GeoUtil)
│   └── dto          외부 API 응답 모델 (WeatherInfo, NotamInfo, NoFlyZoneInfo, SunTimeInfo)
├── api              외부 API 클라이언트 (인터페이스·추상·구현)
│                    ApiClient<T> ─ CachedApiClient<T> ─ Weather/Notam/VWorld/SunTime
├── io               파일 입출력 (FileCacheStore: TTL 캐시, AppDataStore, NoFlyZoneStore)
├── judge            비행 안전 판정 엔진 (FlightSafetyJudge, FlightSafetyReport)
├── controller       MVC 컨트롤러 (DashboardController, SpotController)
└── view             Swing UI (MainFrame + 지도·체크리스트·정보 패널)
```

**설계 적용 개념**: 제네릭(`ApiClient<T>`), 추상 클래스를 통한 캐시 로직 공통화(`CachedApiClient<T>`),
인터페이스 분리, record 기반 불변 DTO, 예외 처리, 파일 입출력.

### 비행 안전 판정 로직
풍속 · 강수 · NOTAM · 공역 교차 · 주간 여부 · 조종 자격 6개 항목을 검사하여
하나라도 NO-GO면 종합 NO-GO, CAUTION이 있으면 CAUTION, 모두 통과 시 GO로 집계합니다.

## 🛠 기술 스택

- **언어/플랫폼**: Java 21, Swing
- **빌드**: Maven
- **라이브러리**: Jackson (JSON/XML), JxMapViewer2 (지도 타일)
- **지도 타일**: Carto Light basemap
- **좌표계**: EPSG:3857(Web Mercator) → EPSG:4326(WGS84) 변환

## 🚀 실행 방법

### 사전 준비
1. 공공데이터포털 / V-World API 키 발급
2. `src/main/resources/config.properties` 작성 (`.example` 참고):
   ```properties
   api.dataportal.key=발급받은_공공데이터포털_키
   api.vworld.key=발급받은_VWorld_키
   ```
   > `config.properties`는 `.gitignore` 처리되어 저장소에 포함되지 않습니다.

### 빌드 및 실행
```bash
mvn compile
mvn exec:java
```
또는 VS Code에서 프로젝트 폴더를 열어 실행 (Extension Pack for Java).

## 🤝 개발 방식: AI 페어 프로그래밍

본 프로젝트는 **사람이 설계와 의사결정을 주도하고, AI(Claude Code)를 구현·탐색 파트너로 활용**하여 진행했습니다.

- **설계 주도(사람)**: 12주차 클래스 설계 보고서를 사람이 작성하고, 이를 *명세*로 삼아 구현을 진행 — AI에게 "무엇을 만들지"의 기준을 사람이 제시
- **구현 가속(AI)**: 설계 명세를 바탕으로 보일러플레이트·DTO·UI 패널 등 반복적 코드를 빠르게 생성
- **탐색·디버깅 협업**: NOTAM 비공개 엔드포인트 분석, V-World 레이어 코드 식별, 좌표 변환 등 까다로운 외부 연동 문제를 AI와 함께 가설→검증 방식으로 해결
- **검증 중심 품질 관리**: AI가 생성한 코드는 **실제 API 호출·빌드·실행으로 검증**한 뒤 반영 (예: 클라이언트별 통합 테스트로 응답 정상 여부 확인)
- **반복적 개선**: UI/UX를 사람이 피드백하고 AI가 반영하는 사이클로 단일 화면 대시보드를 완성

> AI를 *코드를 대신 짜주는 도구*가 아니라, **설계 의도를 빠르게 코드로 구현하고
> 외부 연동의 불확실성을 함께 검증하는 협업 파트너**로 사용한 것이 핵심입니다.
